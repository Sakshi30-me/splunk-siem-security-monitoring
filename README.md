# Splunk SIEM Security Monitoring and Alert Investigation

## Project Overview

This project demonstrates hands-on experience using **Splunk as a Security Information and Event Management (SIEM) platform** to monitor, analyze, correlate, and investigate Windows security events.

The project uses a Windows security dataset containing approximately **12,000 events** and focuses on authentication activity, system activity, event correlation, detection, alerting, and investigation.

The work was performed as a practical security monitoring lab using Splunk and the **TryHackMe Splunk: Exploring SPL** environment/data.

---

## Objectives

* Configure and use Splunk for security monitoring.
* Ingest and analyze a large Windows security event dataset.
* Analyze authentication-related events.
* Analyze Windows system/process activity.
* Correlate different event types to establish an event timeline.
* Develop a security monitoring detection rule.
* Configure a scheduled Splunk alert.
* Investigate events generated by the detection.
* Document investigation findings and recommended response actions.

# 1. Security Event Monitoring

The Windows security dataset was analyzed in Splunk to establish the available event volume and provide a foundation for security monitoring.

The dataset contained approximately **12,000 events**, providing sufficient data for investigating authentication and system activity.

---

# 2. Authentication Event Analysis

Windows authentication activity was investigated using **Event ID 4624**.

The analysis extracted relevant fields including:

* Timestamp
* Event ID
* Target username
* IP address
* Logon type
* Workstation name
* Process name

### SPL

```spl
index=windowslogs EventID=4624
| table _time EventID TargetUserName IpAddress LogonType WorkstationName ProcessName
| sort _time
```

This search was used to examine authentication activity and identify repeated or unusual patterns within the dataset.

---

# 3. System Activity Analysis

Windows process-creation activity was analyzed using **Event ID 1**.

Relevant fields were extracted to examine system activity, including:

* Hostname
* User
* Process image
* Parent process
* Command line

### SPL

```spl
index=windowslogs EventID=1
| table _time Hostname User Image ParentImage CommandLine
| head 50
```

---

# 4. Event Correlation and Timeline Analysis

Authentication and process-creation events were correlated to establish a chronological view of relevant system activity.

The events were categorized as:

* Authentication
* Process Creation
* Other

Only the relevant authentication and process-creation activity was retained for the investigation timeline.

### SPL

```spl
index=windowslogs
| eval event_type=case(
    EventID=4624,"Authentication",
    EventID=1,"Process Creation",
    true(),"Other"
)
| search event_type!="Other"
| table _time Hostname EventID event_type TargetUserName LogonType IpAddress Image ParentImage CommandLine
| sort _time
| head 100
```

This provided a timeline containing **51 relevant events** from the available dataset.

---

# 5. Security Detection Rule

A detection rule was created to identify repeated Windows authentication activity.

### Detection SPL

```spl
index=windowslogs EventID=4624
| stats count by TargetUserName Hostname
| where count >= 2
| sort - count
```

The rule groups successful authentication events by username and hostname and identifies combinations occurring at least twice.

This provides a simple monitoring use case for identifying repeated authentication activity that can be reviewed by a security analyst.

---

# 6. Splunk Alert Configuration

The detection was configured as a scheduled Splunk alert named:

**Windows Authentication Activity Detection**

Configuration:

* **Alert type:** Scheduled
* **Schedule:** Daily
* **Trigger condition:** Number of events > 0
* **Trigger:** Once
* **Action:** Add to Triggered Alerts
* **Status:** Enabled

---

# 7. Alert Investigation

The authentication events identified by the detection were further investigated by grouping activity according to:

* Target username
* Hostname
* Logon type
* IP address

### Investigation SPL

```spl
index=windowslogs EventID=4624
| stats count by TargetUserName Hostname LogonType IpAddress
| sort - count
```

The investigation returned **26 authentication events** and grouped them into multiple username, host, logon-type, and IP-address combinations.

Repeated authentication activity was observed within the results and was reviewed as part of the investigation.

---

# 8. Investigation Findings

The investigation demonstrated how Splunk can be used to:

* Search large volumes of Windows security events.
* Isolate authentication activity.
* Identify repeated authentication patterns.
* Correlate authentication and system activity.
* Build a chronological event timeline.
* Create a detection rule.
* Generate scheduled alerts.
* Investigate events associated with a detection.

The observed repeated authentication activity should be evaluated against expected user, host, and network behavior before determining whether it represents suspicious activity.

---

# 9. Recommended Response

For a production environment, authentication activity identified by this type of detection could be reviewed against:

1. Expected user and workstation activity.
2. Known IP addresses and network locations.
3. Logon types and normal authentication patterns.
4. Related process and system activity.
5. Other security telemetry available in the SIEM.

If activity is determined to be abnormal, additional investigation and appropriate incident-response procedures should be initiated.
